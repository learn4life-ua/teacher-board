# TeacherBoard Next — передрелізна перевірка

Цей чек-лист використовується перед заміною legacy `index.html` новою модульною версією.

## Автоматично перевірено

GitHub Actions виконує два незалежні контури перевірки:

- `Validate TeacherBoard Next` — синтаксис JavaScript, import-шляхи, критичні модулі, DOM-контракт `preview.html` і статичний контракт лазера;
- `Browser Smoke TeacherBoard Next` — реальний Chromium для legacy-міграції, desktop, tablet touch та Android/Pixel viewport.

Успішний browser smoke перевіряє:
- міграцію `teacherboard.v1` → `teacherboard.v2` у Chromium;
- перенесення старого canvas-знімка в locked image object і старого тексту в text object;
- повторне відкриття після міграції без дублювання об'єктів;
- rollback міграції: при помилці запису v2 стара v1-копія відновлюється, частковий v2 і migration flag не залишаються;
- меню фігур закрите на старті, а активним є «Вибір»;
- створення фігури як `.scene-object`;
- шторку як окремий об'єкт та undo/redo для неї;
- створення тексту та графіка;
- наявність числових підписів шкали й назв осей графіка;
- відкривання responsive drawer;
- додавання лінійки на desktop/tablet/Android;
- побудову відрізка лінійкою, двох променів транспортиром, кола та дуги циркулем на desktop;
- збереження object state у `teacherboard.v2`;
- додавання та дублювання сторінок;
- реальне завантаження PNG на desktop;
- desktop, tablet і Android сценарії без browser console/page errors.

`Validate` додатково перевіряє, що laser module підключений, має `pointerdown/pointermove/pointerup`, activation overlay і не повернувся до нестабільної залежності від `setPointerCapture`.

Автоматичні тести не замінюють короткий реальний touch-тест на фізичному пристрої.
