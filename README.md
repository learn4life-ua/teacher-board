# TeacherBoard

TeacherBoard — легка інтерактивна онлайн-дошка для викладачів і репетиторів, орієнтована насамперед на заняття з математики.

Проєкт працює без реєстрації та серверної частини й розрахований на GitHub Pages.

## Поточні можливості

- сторінки для роботи під час заняття;
- ручка, маркер і гумка;
- текст, лінії, стрілки та прості фігури;
- фони: чистий, клітинка, лінії, координатна сітка;
- математичні символи;
- вставка зображень і скріншотів із буфера;
- undo / redo;
- автозбереження у браузері;
- експорт сторінки у PNG;
- повноекранний режим;
- шторка;
- лазерна указка;
- математична панель.

## Поточний технічний стан

Робоча версія історично розвивалася через базові файли та послідовні доповнення `v2`, `v3`, `fixes-*`. Це дозволяло швидко додавати функції, але тепер ускладнює розвиток геометричних інструментів, об'єктів і масштабування.

Тому проєкт переходить до модульної архітектури без різкого переписування робочої версії.

## Нова архітектура

Основні принципи:

- фон, рукописне малювання, редаговані об'єкти та геометричні інструменти працюють на окремих логічних шарах;
- фігури після створення залишаються окремими об'єктами;
- лінійка, транспортир і циркуль є інтерактивними інструментами, які можна рухати, повертати та масштабувати;
- zoom і pan застосовуються до всієї сцени узгоджено;
- один центральний стан визначає активний інструмент;
- великі зміни виконуються в окремих гілках і потрапляють у `main` тільки після перевірки.

Докладний опис: [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md).

## План розвитку

1. Винести базовий стан дошки, history, storage та viewport у модулі.
2. Створити object manager та режим вибору.
3. Перенести фігури на об'єктну модель.
4. Виправити масштабування сцени та координатної площини.
5. Реалізувати лінійку як повноцінний інтерактивний інструмент.
6. Реалізувати транспортир.
7. Реалізувати циркуль.
8. Поступово перенести решту функцій у модулі.
9. Після стабілізації прибрати `v2`, `v3`, `fixes-*` із робочого завантаження.

## Структура міграції

Папка [`src/`](src/) призначена для нового модульного коду. Папка [`legacy/`](legacy/) зарезервована для контрольної копії старої архітектури після завершення міграції.

Робоча версія на GitHub Pages не повинна ламатися під час цієї перебудови.
